## Phase goal

Users can run all three initial emergencies (Oil Temp High, Electrical Failure, Engine Fire) and see each one react to what they do: gauges move, ignored failures escalate, handled failures recover. (ROADMAP Phase 3, Mode mvp, goal kept verbatim.) This plan closes the UAT gap found after test 12: the real engine page marks an out-of-range value with a coloured box and a pointer in the band colour, the trainer only colours the band.

<objective>
Restyle the MFD gauges by the band their live value is in: yellow gives a yellow box behind the label and the numeric value, dark text and a yellow pointer; red gives red boxes, white text and a red pointer; green stays as it is. A pure mapping decides the look, a pure function derives the band colour of a reading from the quantity data, and the gauge components only draw what they are told.

Purpose: UAT gap (owner, 2026-10-23, with photos of the real engine page): "the real display marks an out-of-range value with a coloured box and a pointer in the band colour; the trainer does not."
Output: gauge-alert.ts, BarGauge, ArcGauge and MfdFrame changes, unit tests of the mapping and of the drawn gauges, an e2e spec on the oil temperature run, one owner-review item.
</objective>

## What the photos show (facts for the executor, read the photos once to confirm)

- Oil pressure in the low yellow band: a yellow rounded box behind the label and another behind the value, black text in both, the pointer above the bar is a yellow filled marker; the red band to its left and the green band to its right are drawn as usual.
- Fuel quantity in the red band: a red rounded box behind the label and another behind the value, white text in both, the tank marker is red with its letter in white.
- The gauges in green (oil temperature, coolant, gearbox, fuel temperature, fuel pressure, the two arc gauges at their readings) have plain text and a white pointer or needle.
- No photo shows an arc gauge outside its green band.

## Defaults used by this plan

| ID | Default | Why |
|----|---------|-----|
| C-66 | Styles: tone green and none: today's look (label grey, value white, pointer white, no box). Tone yellow: box fill yellow, text the dark glass colour, pointer yellow. Tone red: box fill red, text white, pointer red. The yellow, red and green fills are the existing MfdFrame values; the dark text is the screen fill value | The photos; "glass colours follow the existing palette" |
| C-67 | The tone is the colour of the band the live value falls in, computed by `toneOf(quantities, id, value)` in gauge-alert.ts through the QuantitySet's own band lookup (a value on a bound belongs to the lower band, below the minimum the first band, above the maximum the last), so the boundary rule exists once. MfdFrame calls it per gauge with the reading it already draws | Driven by the live quantity band; no second implementation of the band rule |
| C-68 | BarGauge and ArcGauge get an optional `tone` prop defaulting to green. In green nothing is added to the rendered tree; in yellow and red the gauge group carries `data-alert` with the tone, and each box carries `data-alert-box` with `label` or `value` | The base readings are all green, so existing vnode tests and the static-text gates see an identical tree |
| C-69 | A box is a rounded rectangle (radius 2) behind its text: height the font size plus 4, top one unit above the cap line of the text, side padding 3 (2 on the 130 wide map strip if the pair would not fit). Its width comes from `textBoxWidth(text, fontSize)` in gauge-alert.ts, an estimate per character that the executor calibrates once against the real fonts in the browser (getBBox of the worst-case label and value of every gauge) and records in the file comment. The label box starts at the label's left edge, the value box ends at the value's right edge; if a worst-case pair cannot fit the gauge width the SUMMARY reports the numbers; no font is shrunk and no text is shortened | Boxes must contain their text without a text measurement at render time; G-0 forbids shortening static labels |
| C-70 | The arc gauges follow the same rule for their label (box centred above the arc), their readout (box centred under the hub) and their needle colour; the unit line below the readout stays plain. No photo shows this; it is the same display logic as the bars and is listed for the owner (item in PANEL-REVIEW) | The files named by the gap include ArcGauge; "follow the photo" has no arc case, the least surprising reading is one rule for the whole page |
| C-71 | The colour constants GREEN, YELLOW and RED and the dark glass colour move into gauge-alert.ts with unchanged values; MfdFrame imports them and keeps its exported SCREEN_FILL with the same value | One palette, no circular import (gauge-alert.ts imports nothing from the frames) |
