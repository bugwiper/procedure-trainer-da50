## Phase goal

Users can run all three initial emergencies (Oil Temp High, Electrical Failure, Engine Fire) and see each one react to what they do: gauges move, ignored failures escalate, handled failures recover. (ROADMAP Phase 3, Mode mvp, goal kept verbatim.) This plan delivers ROADMAP criterion 2: an ignored failure that passes its red line escalates to a named outcome that appears in the debrief.

<objective>
Add named outcomes: scenario data that ends the run when a predicate holds for a hold time, the live run completing itself as FAIL, grade finding the same outcome by replaying the same simulation, the debrief naming it, and the lint rule that keeps outcome data sane. ENG OIL TEMP gets its engine failure outcome.

Purpose: D-06 (escalation to a named outcome that ends the run as FAIL), D-07 (PASS and FAIL only), SCN-06 (escalation to named outcomes).
Output: schema `outcomes`, hold timers in the simulation, grade with `outcome`, the session's automatic completion, the reason line, lint L13, golden fixtures with outcome cases, an e2e escalation case.
</objective>

## Defaults used by this plan

| ID | Default | Why |
|----|---------|-----|
| C-24 | Outcome format: `outcomes` is a list (at most 4, default empty) of strict objects id (step-id pattern), text (1 to 12 words, own words, shown in the debrief), when (a Predicate of the closed vocabulary) and hold_s (0 to 600) | Additive, format stays 1; the bounds cap every loop (Security); a hidden quantity covers cases without a CAS rule, so the vocabulary needs no extension (RESEARCH) |
| C-25 | After the physics of each step every outcome predicate is evaluated over the current controls, the scenario baseline and the quantities; its held time grows by STEP_MS while it holds and drops to 0 when it does not; the first outcome in declared order whose held time reaches hold_s fires with t equal to the state time after that step; no step follows an outcome | One rule for the live run and the replay |
| C-26 | grade simulates up to completedAt; with an outcome, the graded log is the prefix of the events whose t is at most the outcome time; GradeResult gains outcome (id, text, t, or null); the reason list starts with the outcome reason, followed by the R8 reasons | The run ends at the outcome; the outcome is the most salient cause (D-06) |
| C-27 | The debrief reason line of an outcome reads "The failure escalated: TEXT." with the scenario's outcome text | D-06: the debrief names the outcome; the missed steps stay in the outline |
| C-28 | ENG OIL TEMP outcome: id engine_failure, text "Engine failure from overheating", when oil_temp_c at or above a threshold above the value a do-nothing run reaches in 20 s from 128 and below the P1-b target of plan 01 (140 proposed), hold_s 15 proposed | D-06 example; instructor-review item A4 |
