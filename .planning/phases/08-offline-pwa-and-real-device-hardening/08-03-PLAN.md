## Decisions (assumptions taken in planning; the owner may veto any of them)
Owner decisions D-05, D-09 to D-11, D-13 and D-14 of `08-CONTEXT.md` apply.
- **L-01 Pure rules.** `src/ui/pwa/update.ts` holds the logic that needs no browser: `updateNoticeShown(state, screen)` (true only for the `free` screen; a `Record<Screen, boolean>` table in the test makes a new screen a compile error), `shouldCheckForUpdate(lastCheckMs, nowMs)` with the 30 minute gap, and the reload gate (a reload is allowed once, only after the user asked). `register.ts` is the thin effectful glue around the browser objects and is covered by the browser spec.
- **L-02 State of the notice.** Two ways into "update available": a waiting worker (the user's tap sends SKIP_WAITING, then the page reloads on `controllerchange`) and a stale tab (the controller changed without this tab's request, so a tap reloads directly). Both show the same label.
- **L-03 Labels.** Fixed strings exported from `update.ts` (the notice sentence, the button label, the two About line forms), so the device checklist and its test quote the code and cannot drift.
- **L-04 Placement.** Bottom edge of the panel area, centred, in the style of the existing `.rotate-hint` (no layout shift, `pointer-events` only on the button, button at least 44 px), clear of the Full panel button; Claude's discretion for details.
