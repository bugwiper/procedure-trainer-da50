## Decisions (assumptions taken in planning; the owner may veto any of them)
Owner decisions D-01 to D-04, D-09, D-10 and D-14 of `08-CONTEXT.md` apply.
- **L-01 Layout.** The pure functions live in `scripts/pwa/precache.ts` (node only, unit-tested), the Vite glue in `scripts/pwa/plugin.ts`, the worker as plain JavaScript in `scripts/pwa/sw.js` (the Node tsconfig has no WebWorker lib and the DOM lib of the Playwright types would clash with one; a plain file with two replaced marker lines stays lintable). `scripts/` is already covered by `format` and `format:check`.
- **L-02 Cache strategy.** Cache-first for precached same-origin GET; navigation inside the scope answers with the cached `index.html` whatever the query string; all else goes to the network untouched; no response is ever added to a cache after install.
- **L-03 Registration.** `registerServiceWorker()` in `src/ui/pwa/register.ts` does nothing unless `import.meta.env.PROD` and `'serviceWorker' in navigator`; swallows rejections; treats a resolved `undefined` as no worker (Playwright block mode). It returns nothing in this plan; 08-03 extends it.

<objective>
Make the app work offline: a Vite plugin stamps a hand-written worker with the build id and the precache list, the page registers it under the base path, and Playwright proves the offline reload and the full flow with the network off.
Purpose: PLT-02 "App installs as a PWA and works offline" (the offline half); ROADMAP criterion 2 and the base-path half of criterion 3.
Output: `scripts/pwa/`, `src/ui/pwa/register.ts`, the Playwright default `serviceWorkers: 'block'`, `e2e/pwa-offline.spec.ts`, `e2e/support/pwa.ts`, `tests/pwa-precache.test.ts`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| network to cache | files fetched at install become the offline truth |
| worker to page | the worker answers requests of the whole scope |
| repo to public/ | everything in public/ is published and precached |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-01 | Tampering | sw.js fetch handler | medium | mitigate | answers only same-origin GET for precached URLs and the exact shell navigation; nothing is added to a cache after install; scope is the base path; unit and e2e cases |
| T-08-02 | Denial of service | stale or half-installed precache | medium | mitigate | install uses cache reload and fails as a whole; old worker stays until the new one installs; build id changes with any file; update flow in 08-03 |
| T-08-03 | Information disclosure | precache of unintended files | medium | mitigate | the list comes only from the build output and public/; the independent directory walk in the spec fails on any extra or missing file; private photos, AFM and paid-pack plaintext are never in either source |
| T-08-SC | Tampering | npm installs | high | accept | no package is added in this plan (hand-written worker, plain Vite plugin); nothing to audit |
</threat_model>
