## Decisions (assumptions taken in planning; the owner may veto any of them)
Owner decisions D-14 to D-18 of `07-CONTEXT.md` apply.
- **L-01 (D-14) Seeds.** One exported pure function in `session.ts`, `retrySeeds(onset, variant)`, returns the seeds a retry reuses: both as recorded (the onset record with its seed on a Realistic run, the variant record on every level). The owner's alternative (a new seed unless the run was a Realistic one) is a change of that one function and of its test. `start(opened, realistic)` takes an optional second argument with the two records and then does not draw; the draws of a normal start are unchanged (same order of `rng` calls), so no recorded run changes.
- **L-02 (D-14) Retry.** `session.retry()`: debrief screen only, ignored while busy. It ends the run in hand like `closeDebrief` (drop the run, clear the flags), clears the result, recording, hint, sheet, decisions and the Further actions modal, and starts the scenario of the debrief (`session.scenario`, the file's own) through the same `start` as a normal run with the level and mode kept and `retrySeeds`. An illegal baseline is kept as a load failure like `begin` does.
- **L-03 (D-14) Next situation.** `session.nextSituation()`: debrief screen only, not busy. It lists the choices (`listChoices`, all allowed packs in manifest order), takes the entry after the current one (the session keeps the `ScenarioRef` of the opened scenario; wrapping to the first; a single entry gives the same one), cleans up like a leave (`toFreePanel` semantics, which keep mode and level), opens its briefing through `openBriefing` with a flag that keeps `modePicked` and `levelPicked`, then: Realistic and the scenario declares an onset starts the run at once; Realistic without an onset sets `levelPicked` false (the level card, mode kept); Easy and Medium show the briefing. It uses the existing `loading` wrapper (busy, busy key `session.next`) and a load failure is shown by the existing message.
- **L-04 Debrief buttons.** `Retry` (test id debrief-retry, primary, first in the action row), `Next situation` (debrief-next), `Back to panel` (debrief-back, unchanged). The 400 ms shield of the modal covers the tap that completed the run.
- **L-05 (D-15) The README section.** Heading `## Writing a scenario` after `## Scenario files` (that short section is folded into it). Fenced blocks of the section carry the info string `toon example` (one complete scenario) or `toon fragment` (a piece). The example is a small own-wording toy that exercises every part a beginner needs (source block, disclaimer, briefing, initial state, annunciations, a checklist in table form with number marks, two groups of steps, a forbidden item, an outcome, an onset with a cue, a flight profile and the further section); its text is not AFM text (the content policy keeps real checklist wording to the shipped files). It must pass `checkScenario` against the DA50 RG environment, which `tests/readme-guide.test.ts` proves.
- **L-06 (D-18) Review list.** The section "Phase 7: owner review" of `docs/PANEL-REVIEW.md` lists as numbered items every owner review point of the three plans (see task 3).
- **Owner review points of this plan:** the retry seed rule, the next-situation rule, the README section.
