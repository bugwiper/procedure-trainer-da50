## Decisions (assumptions taken in planning; the owner may veto any of them)
Folded todo of D-03: `2026-10-28-pitot-stall-heat-cas.md`. This plan is the fourth plan of the phase (D-03 allows it): the first three plans fill the order of D-01 and are complete without it. Plans 01 to 03 supply the advisory level, the quantity and parameter patterns and the flight state this plan reuses.
- **H-01 Rules.** `pitot_heat` (text PITOT HEAT, caution, state check on `sw.pitot_stall_heat` is off), `stall_heat` (text STALL HEAT, caution, the same state check) and `stall_heat_ground` (text STALL HEAT, caution, band check on the hidden quantity `stall_heat_timer_s` in `cut`). The last two never hold together (the switch off resets the timer), so one STALL HEAT chip shows at most. A faulty system as a third cause is not built: no source describes a fault input, and a later scenario adds a parameter and a rule.
- **H-02 Ground cut-out.** `stall_heat_timer_s` (hidden, 0 to 60 seconds, bands warm to 5 and cut to 60) is a rate model: it counts up one second per second while the switch is on and the parameter `ground_roll` is above 0, and is held at 0 (a reset within one step) otherwise, so airborne the message disappears at once. The 5 s are an instructor-review value (`STALL_HEAT_CUTOUT_S` in the quantity data, read by the band). On the ground the heat counts as on from the start of the run: there is no switch-on event to arm it, because a reaction on a latching control would consume the event and break the double-tap retract of the gesture contract.
- **H-03 Consequence for the ground situations (owner question).** The three ground situations start with the heat on (the registry default), so with H-02 a STALL HEAT chip appears 5 s after their start (Easy and Medium) or 5 s after the onset (Realistic). That is what the owner describes for the real aircraft. The alternative (those situations start with the heat off and show both messages from the start) breaks the Realistic clean start (lint L14), so it is not taken. The owner confirms or asks for a different default.
- **H-04 The icing situation.** Its checklist asks the pilot to switch the heat on, so the start state has it off, which now fires two messages at the start. Lint L14 requires the Realistic start to be message-free and one initial control set serves every level, so the heat-off start becomes the single variant `heat_off` (weight 1, controls `sw.pitot_stall_heat` off, applies nothing, an own-wording cause line for the debrief): Easy and Medium start with the heat off and both messages, listed in `annunciations`; Realistic starts with the registry default (on) and the simulation switches it off at the onset, which shows both messages next to the ice cues. `sw.pitot_stall_heat` leaves `initial.controls`. The briefing line "no message is shown" is reworded for the two messages. If lint rejects a single variant, stop and report: it is a decision for the owner, the step is not weakened.
- **H-05 Not built.** A heat fault input; the electrical dependence of the heat (breaker and bus effects stay in their todo); a message for the angle-of-attack system.
