## Decisions (assumptions taken in planning; the owner may veto any of them)
Owner decisions D-11 to D-13 and D-14 to D-18 of `06.1-CONTEXT.md` apply. Plans 01 and 02 have created the layout module, the reference table, the column and the synthetic vision.
- **V-01 (D-11) Scale and pointer.** The constants (`VS_SCALE_MAX_FPM` 2000, which a test ties to the max of the quantity `vertical_speed_fpm`; the half height in region units, 84; the tick step 500; the numeral values 1000 and 2000) and the strip rectangle (starting x 439, width 22, y 66 to 234, zero at the attitude centre height 150) live in `pfd-layout.ts`. The pure function `verticalSpeedPointerPx(value)` returns the pointer's offset from the zero line in region units: minus the clamped reading divided by the maximum times the half height, the negative zero turned into 0 (like `pitchShiftPx`), a missing or non-finite reading read as the base of the quantity. It uses `+ - * /`, clamping and rounding only. `pfd-layout.ts` already imports from `avionics.ts`, so the function goes where it makes no import cycle (in `pfd-layout.ts` with an exported `readingOr`, or in `avionics.ts` with the constants passed in); decide by the typecheck.
- **V-02 (D-11) The strip.** `src/ui/panel/frames/VerticalSpeedScale.tsx` is a pure function component (no hooks). Group with test id `pfd-vs`: the strip rectangle in a translucent light grey (starting `#c9d0d8` at about 35 per cent so that a black pointer reads on any view), nine tick marks (the zero mark and the 500 steps, the thousands longer), the numerals 1 and 2 at plus and minus 1000 and 2000 (size 6, static), and the pointer group `data-vs-pointer` with transform `translate(0 y)` (two decimals, never a negative zero), an arrow with black fill and a thin light outline (starting 7 wide, 8 high, tip towards the tape). No digital number; `data-vs-readout` and `verticalSpeedText` are removed. Tests and the e2e read the pointer from its transform.
- **V-03 (D-12) QNH.** New quantity `qnh_hpa` in `quantities.ts` after the other static display values: unit hPa, range 950 to 1050, base 1013, one unmarked band, no model; the header comment of the table names it a static display value whose base is a layout assumption. `avionics.ts` gets `PFD_QNH_QUANTITY` and `qnhReadout(value)` (whole hPa, a missing or non-finite reading reads the base). `PfdFrame` draws the value in the glass digits at size 8 in the turquoise of the glass header (the constant `TAB_SELECTED_BORDER` of `MfdFrame.tsx` is exported under a neutral name such as `GLASS_TURQUOISE`; the header keeps using it) with `data-qnh-readout`, and the unit HPA at size 6 beside it, under the FT label of the altitude tape (starting: value right-aligned at x 398, unit from x 400, baseline y 290). The old baro box and VS box (rectangles and texts) are deleted. A scenario can set the value through its start quantities with no code change; no shipped scenario does and no lint rule is added. It does not correct the altitude.
- **V-04 Tests that must move.** `tests/pfd-live.test.ts` (the `verticalSpeedText` cases and the `data-vs-readout` cases become pointer cases), `tests/avionics.test.ts` (Table D5: the label VS and the text 1013 HPA are gone, the numerals 1 and 2 and the readout texts are in; the PFD test id order gains `pfd-vs`), `tests/physics.test.ts` (`STATIC_DISPLAY` gains `qnh_hpa`), `e2e/pfd.spec.ts` (the `VS` locator and the label case).
- **V-05 Documents (D-18).** The Phase 6.1 section of `docs/PANEL-REVIEW.md` lists, as numbered items, every owner review point of the three plans: (1) the severity order top to bottom and the growth upward; (2) the width, row height, weight and place of the CAS rows; (3) the four synthetic views, the haze, the terrain in the cloud scene, the static dashes on the take-off runway; (4) the tape opacity; (5) the compass backing and the aircraft symbol on the new background; (6) the vertical speed scale: linear, plus and minus 2000, black pointer, no digital number; (7) QNH in hPa, display only, settable by a situation and by `?q=qnh_hpa:`; (8) what was not added (the list of D-02) and the deferred options; (9) the results of the final gates. `tests/panel-review.test.ts` pins the heading order: it moves to Phase 6.1 as the last section and gets a case like the earlier phases for the numbered items.
