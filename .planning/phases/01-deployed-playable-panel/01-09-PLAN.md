## Phase Goal

**As a** DA50 RG pilot or student, **I want to** open the deployed trainer on my desktop, tablet or phone and operate the panel's switches, guarded switches, levers and buttons by mouse or touch, **so that** I can later rehearse emergency procedures by actually operating the controls.

This plan delivers the phone slice of that goal: the true-to-aircraft panel stays intact, and the user zooms into any region to operate its controls at full tap size.

<objective>
Add phone region zoom (PNL-09, D-20) by manipulating the root svg viewBox: region tap to zoom in, a 'Full panel' button and double tap to zoom out, pinch and pan, with gesture arbitration so zoom gestures never emit control events and never fight control drags. The panel layout data from plan 03 is not touched.

Purpose: PNL-09 (zoom into a region with enlarged hit targets without changing the true layout), PNL-06 (gestures are never graded), PNL-05 (usable on phones). Decisions D-19 (layout never relocates), D-20 (zoom via viewBox; full tap size in zoomed view on the smallest phone; desktop and tablet without zoom) and CLAUDE.md (viewBox manipulation, Pointer Events, custom gesture arbitration rather than a pan/zoom library).
Output: src/ui/panel/viewport.ts, src/ui/panel/zoom.ts, Panel and App wiring, styles, one unit and one e2e spec.
</objective>

```typescript
// src/ui/panel/viewport.ts (pure, no DOM; unit-tested in node)
export function fitScale(view: Size, screen: Size): number;                      // min(screen.w / view.w, screen.h / view.h)
export const ZOOM_PAD: number;                                                    // 10 viewBox units around a region
export const MIN_VIEW_WIDTH: number;                                              // 300 units: pinch-in limit
export function zoomRect(bounds: Rect, viewBox: Size): Rect;                      // bounds padded by ZOOM_PAD, clamped inside the viewBox
export function needsZoom(viewBox: Size, screen: Size, minTargetUnits: number): boolean; // fitScale(viewBox, screen) * minTargetUnits < 44
export function pinchRect(current: Rect, centre: { x: number; y: number }, factor: number, viewBox: Size): Rect; // scale about centre, width clamped to MIN_VIEW_WIDTH..viewBox.w, kept inside the viewBox
export function panRect(current: Rect, dx: number, dy: number, viewBox: Size): Rect; // translate, kept inside the viewBox
// src/ui/panel/zoom.ts (Preact signals plus DOM listeners; never imports the bridge)
export const viewRect: Signal<Rect>;      // starts at the full viewBox
export const isZoomed: ReadonlySignal<boolean>;
export function zoomToRegion(region: Region, viewBox: Size): void;
export function zoomOut(viewBox: Size): void;
export function attachZoomGestures(svg: SVGSVGElement, opts: { registry: Registry; screen: () => Size }): () => void; // returns detach
```

## Probe coverage (spec-less fallback)

PNL-09 was added after the edge probe ran; flagged assumptions instead of probe rows:
- "Phones" means the landscape phone projects; the zoom floor is asserted on the smallest landscape profile (iPhone 15 landscape). In portrait, the rotate hint (D-02) remains the guidance and the widest regions (the switch row) stay slightly under 44 px when zoomed.
- On phones, a background tap inside a region zooms to it; a tap on a control's target always operates the control, at every zoom level. Region tap is disabled on desktop and tablet because they meet 44 px at the full view.
- Pinch and pan are available on every touch device; no pinch library is used (CLAUDE.md: custom viewBox gestures keep arbitration in our hands).

Prohibition recall (PNL-09, PNL-06): the event-integrity prohibition in plan 07 covers zoom gestures (they must never emit events); the relocation prohibition in plan 03 covers the "true layout unchanged" rule. No additional bespoke prohibition.
