## Decisions (assumptions taken in planning; the owner may veto any of them)

- **V-13** WR-03: `frame()` re-arms before it steps and catches what the step throws. The driver gets an optional `onError`; App wires it to a new `session.failRun(error)`, which ends the run without grading, resets the panel to its defaults (as leaving a run does) and shows the error text through the existing load-failure message ("The run stopped because of an error: ..."). Without `onError` the driver logs with console.error and keeps going.
- **V-14** WR-05: the run ends at `MAX_RUN_MS`. `Run.step` does nothing at the cap, the session completes the run there (graded as of the cap, like an outcome but without one), and the debrief prints one line "The run reached the N minute limit." (N derived from MAX_RUN_MS). The simulation and the clock never pass the cap, so a retract after it cannot offset them.
- **V-15** Variants for ENG OIL TEMP and ENGINE FIRE are not cheap or clearly useful now (they need start-quantity variants and the Phase 6 oil pressure model, or are separate scenarios). Listed as the todo `.planning/todos/pending/2026-10-23-variants-oil-temp-and-fire.md`, written in planning.
- **V-16** All phase-end documentation is task 3; the variants todo `2026-10-23-scenario-variants.md` moves to `done/`. STATE.md, config.json, state.json and milestone.lock are not touched.

Purpose: a failing step must not freeze the panel without a word, and a long run must grade the same as it replays.
Output: clock-driver and session changes, a capped Run, a debrief line, tests, and the phase-end documentation.
