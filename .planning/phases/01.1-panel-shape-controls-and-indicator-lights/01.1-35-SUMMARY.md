# Phase 01.1 Plan 35: Log-level retract of the last event Summary

The engine can now remove the last event from the action log (no counter-event) and recompute the state by replaying the remaining log; the bridge keeps signals and lamps in step. Nothing calls it yet; plan 40 wires the gesture (owner finding R3-Z3, engine side).

## What changed

- `src/engine/store.ts`: exported pure `deriveState(registry, events)`; the constructor builds its state from it. `retract(seq)` follows Table S1 with check order unknown-event, consumed, not-last; on success it drops the event, rebuilds the whole state map from the remaining log (never patches one entry), calls the retract listeners once with (event, restored value) and does not call the dispatch listeners. `markConsumed(throughSeq)` raises the watermark (starts at -1; RangeError unless an integer, not below the watermark and below the log length). `consumedThrough` is read-only. `onRetract` returns an unsubscribe function. `dispatch` and `subscribe` are unchanged; the next accepted event after a retract takes seq equal to the log length, so seq stays dense. JSDoc on `retract` and `markConsumed` states the Phase 3 rule. No clock, timer or browser global entered `src/engine`.
- `src/ui/bridge.ts`: added `bridge.retract(seq)` (returns the store result) and an `onRetract` subscription that sets the signal of the restored control, so computed lamps follow. `actuate` and `window.__panel` (four read-only members) are unchanged.
- `tests/store.test.ts`: cases for deriveState, retract on a two-state switch, three-state toggle, lever detent, breaker and guard (guard open retracted blocks the switch again; switch retracted leaves the guard open), seq reuse, not-last / unknown-event (-1, length, 1.5, NaN, Infinity, empty log) with no state, log or notification change, listeners, the watermark rules and RangeError cases, and two seeded walks (4 seeds each) of 300 steps over the real registry using a local linear congruential generator.
- `tests/bridge.test.ts` (new, node environment): the flaps lever to T/O lights `lt.flap_to`, retract returns lever, lamp and log to the start; a refused retract changes no signal; a mixed sequence leaves every signal equal to the store snapshot.
- `.planning/todos/pending/2026-10-21-retract-consumed-events-phase3.md`: the rule for the Phase 3 planner (reactions call `markConsumed`; retract is only valid for the newest event until a reaction consumed it; the pair window stays a UI rule; cancel what a retracted event armed).

## Mutation check

In the random-walk tests the rebuild (`this.state = new Map(Object.entries(next))`) was replaced by a one-line patch of a single entry (`state.set(event.id, default)`); 8 walk tests failed. The line was restored and the full suite is green again (store.ts matches the committed file).

## Assumptions taken

- `deriveState` returns a plain `Record<ControlId, StateId>` rather than a Map, matching `snapshot()` so tests compare them directly.
- `markConsumed(-1)` on any log is accepted as a no-op (an integer, not below the watermark, below the length).
- Process note: the store implementation was written before the first test run (the tests were written first in the file, but the red run was not observed for the store; for the walk it was observed through the mutation check above).
