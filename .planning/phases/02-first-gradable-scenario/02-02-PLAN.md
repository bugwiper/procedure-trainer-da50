## Data tables

The file format, the predicate vocabulary (Table F3, including the travel-percent formula and the baseline rule) and the manifest format (Table F4) are in 02-01-PLAN.md.

Table P1, the pack seam (src/scenario/packs.ts; PLT-03, D-20):

| Name | Contract |
|------|----------|
| PackMeta | `{ id, title, free, scenarios: readonly { id, title, file }[] }` |
| PackSource | `{ id, files: readonly { name, text }[] }` (name = base name without `.toon`) |
| PackProvider | `listPacks(): Promise<readonly PackMeta[]>`, `loadPack(id): Promise<PackSource>` |
| AccessPolicy | `canAccess(packId): boolean \| Promise<boolean>`; `OPEN_ACCESS` returns true (open in v1) |
| createPackProvider | `({ manifests, loaders })`: keys are `/scenarios/<pack>/<name>.toon`; manifests are text, loaders are lazy text loaders; listPacks parses manifests with parseManifest (an invalid manifest throws an Error naming its path; the validate command of plan 05 catches it before a build) and never calls a loader; loadPack calls only the loaders of that pack folder |
| ScenarioRef | `{ pack, scenario }` (scenario = manifest entry id) |
| openScenario | `(source: { provider, policy }, env: AircraftEnv, ref) => Promise<OpenResult>`; OpenResult = `{ ok: true, scenario }` or `{ ok: false, reason: 'denied' \| 'missing' \| 'load-failed' \| 'invalid', issues }`; order: policy, manifest entry, loadPack (a rejection becomes load-failed), file by entry.file, parseScenario, lintScenario, scenario id equals entry id |
| VITE_PACKS (packs-vite.ts) | createPackProvider over the two `import.meta.glob` calls of RESEARCH Pattern 6: manifests `/scenarios/*/pack.toon` eager, scenario files `/scenarios/*/*.toon` lazy, both with query `?raw` and import `default` |

Table G1, grading types (src/engine/grading.ts):

| Type | Shape |
|------|-------|
| Recording | `{ scenarioId, completedAt, events: readonly { t, id, value }[] }` in log order |
| GradeResult | `{ scenarioId, result: 'pass' \| 'fail', reasons, steps, branches, orderViolations, harmful }`, JSON-serialisable (no Map, Set, undefined or Date) |
| StepVerdict | `{ id, group, severity, credited, enteredAt }`; enteredAt = log index of the event after which `done` became and stayed true, null when not credited, -1 when true from the baseline |
| BranchVerdict | `{ path, status: 'applies' \| 'not_applicable' \| 'open' }`; path = dot path in the decoded file, for example `procedure.0.branches.1` or `procedure.0.branches.1.nodes.3` |
| OrderViolation | `{ group, expected, before, critical }`: step `expected` was declared before step `before` but last entered after it |
| HarmfulEntry | `{ id, text, t, seq, failsRun }` |
| Reason | `{ kind: 'critical_missed', count }`, `{ kind: 'order', group }`, `{ kind: 'forbidden', id }` |

Table G2, grading rules (D-09 to D-13; RESEARCH Pattern 3):

| # | Rule |
|---|------|
| R1 | ctx0 = { controls: baseline, baseline, quantities: initial quantity values } (baselineOf, initialQuantities) |
| R2 | Branch status: decided_at run gives open; decided_at start under an applying parent gives applies when `when` holds on ctx0, else not_applicable; a branch under a not_applicable parent is not_applicable, under an open parent open |
| R3 | A step is graded only when every enclosing branch applies (a group outside any branch is graded); a forbidden item is watched only when its `when` is absent or holds on ctx0 |
| R4 | Replay: start from the baseline, apply the recorded events in log order (never sorted by t), evaluate after every event with the initial quantities (fixed in phase 2, D-07) |
| R5 | Steps: entering true sets enteredAt to the event index, turning false clears it; forbidden: every false-to-true transition after an event appends a HarmfulEntry with that event's t and index, even if reverted later (A5) |
| R6 | credited = done holds after the last event (holds at Procedure complete, D-09) |
| R7 | Ordered group: for credited steps in declared order, every pair (a before b) with enteredAt(a) > enteredAt(b) is one violation; uncredited steps give none; critical = group.order_critical (D-12) |
| R8 | PASS iff every graded critical step is credited, no harmful entry has failsRun and no violation is critical (D-10 to D-12); reasons in that order: critical_missed with the count, order per order-critical group, forbidden per failsRun id |
| R9 | All output lists follow declared scenario order (depth-first), not object-key order; no clock, no randomness; the same inputs give a JSON-identical result |

Table R1, golden recordings (one file tests/fixtures/recordings.json, an object whose keys are the names below and whose values are Recordings; D-13):

| Name | Scenario | Events (t ms: id value) | Expected |
|------|----------|-------------------------|----------|
| golden | eng-oil-temp-green | 8000 lv.power p60; 15000 lv.cowl_flap open | pass, no reasons, no harmful |
| do-nothing | eng-oil-temp-green | none | fail, critical_missed count 2 |
| forbidden | eng-oil-temp-green | 5000 lv.power p80; 9000 lv.power p60; 14000 lv.cowl_flap open | pass, one harmful entry power_increased at t 5000, seq 0 |
| forbidden-reverted | eng-oil-temp-green | 4000 p80; 6000 p75; 9000 p85; 12000 p60; 15000 cowl open | pass, two harmful entries (seq 0 and 2) |
| toggle-back | eng-oil-temp-green | 6000 p60; 9000 cowl open; 12000 cowl closed | fail, open_cowl_flap not credited, critical_missed count 1 |
| wrong-order | ordered-critical | 6000 cowl open; 9000 lv.power p60 | fail, one violation (expected reduce_power, before open_cowl_flap, critical true), reason order |

tests/fixtures/scenarios/ordered-critical.toon is a synthetic copy of the blueprint whose group `immediate` is ordered and order-critical (same steps in the order power, then cowl flap) and whose branches are reduced to the green branch; its file header says it is a test fixture.
