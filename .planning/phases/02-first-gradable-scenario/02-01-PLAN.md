## Data tables

Table F1, scenario file format 1, top level (every object is a `z.strictObject`, so an unknown key is an error; "words" are whitespace-separated tokens, one shared `wordCount` helper):

| Key | Type and rule |
|-----|---------------|
| format | the number 1 |
| id | `^[a-z0-9]+(-[a-z0-9]+)*$` |
| title | 1 to 18 characters |
| source | object: document, issue, section (non-empty after trim), verified (`^\d{4}-\d{2}-\d{2}$`); CONTENT-POLICY section 4 |
| disclaimer | one of `DISCLAIMER_IDS` from src/scenario/disclaimers.ts (`training-aid`) |
| briefing | object: situation (1 to 60 words) |
| initial | object: controls (record control id to state id), quantities (record quantity id to finite number) |
| annunciations | list of CAS rule ids (strings), may be empty; plan 08 checks it against the rule table |
| procedure | list of at least one node (Table F2) |
| forbidden | optional list, default empty, of: id, text (1 to 12 words), trigger (predicate), fails_run (optional boolean, default false, D-11), when (optional predicate) |

Table F2, procedure nodes (discriminated by `kind`; ids of groups, steps and forbidden items match `^[a-z][a-z0-9_]*$`):

| kind | Fields |
|------|--------|
| line | text (1 to 12 words), a non-graded checklist line (D-04) |
| decision | text (1 to 12 words), branches (list of at least one branch object, written without `kind`) |
| branch | `kind: branch` plus the branch object fields, a standalone branch inside a node list |
| group | id, ordered (boolean), order_critical (optional boolean, default false, D-12), steps (list of at least one step) |

Branch object: label (1 to 8 words, ends with a colon), when (predicate), decided_at (optional `start` or `run`, default `start`), nodes (optional list of nodes, default empty). Step: id, severity (`critical`, `standard`, `optional`), text (1 to 12 words), done (predicate). D-23 "a step or group bound to a condition" is expressed by placing it inside a branch; forbidden items carry their own optional `when`.

Table F3, predicate vocabulary (discriminated by `check`; `op` is one of `lt`, `lte`, `gt`, `gte`; nothing is evaluated as a string, D-22):

| check | Fields | True when |
|-------|--------|-----------|
| state | control, is | the control is in state `is` |
| state_in | control, in (at least one) | the control is in one of the states |
| travel | control, op, value (0 to 100) | travel percent of the control OP value (detent levers only) |
| travel_rel | control, op, delta (-100 to 100) | travel percent OP (baseline travel percent + delta) |
| quantity | quantity, op, value (finite) | the quantity value OP value |
| band | quantity, in (band ids, at least one) | the band of the quantity value is one of them |

Travel percent = `Math.round(pos * 1000) / 10` with `pos` the detent position of the current state (RESEARCH Pitfall 6: p55 is exactly 55). The baseline is the registry defaults overlaid with `initial.controls`; the quantity values are the idle values overlaid with `initial.quantities`. The evaluator is plan 02's (src/engine/predicates.ts); this plan validates the shapes and resolves the references.

Table F4, pack manifest `scenarios/<pack>/pack.toon` (schema and parseManifest here; plan 02 writes the file. The pack id is the folder name; the scenario count is the list length, never a field; D-20 names the file `pack`, the `.toon` extension is the research recommendation A3 and an assumption to record):

| Key | Type and rule |
|-----|---------------|
| format | the number 1 |
| title | non-empty |
| free | boolean |
| scenarios | list of at least one: id (scenario id), title (1 to 18 characters), file (base name without `.toon`) |

Table F5, DA50 RG quantities in src/aircraft/da50rg/quantities.ts (the AFM 02-05 limits already cited in src/ui/panel/frames/MfdFrame.tsx; plan 08 makes the MFD read them from here):

| id | unit | min | max | idle | bands (id, colour, upper bound) |
|----|------|-----|-----|------|---------------------------------|
| oil_temp_c | °C | -25 | 150 | 15 | low_yellow yellow 50; green green 115; high_yellow yellow 125; high_red red 150 |
| oil_pressure_bar | bar | 0 | 9 | 0 | low_red red 2; low_yellow yellow 3.5; green green 7; high_yellow yellow 7.5; high_red red 9 |

Band rule: bands ascend contiguously from min and the last bound equals max; a value belongs to the first band whose bound is at least the value; below min it is the first band, above max the last (so 125 is high_yellow and 128 is high_red).
