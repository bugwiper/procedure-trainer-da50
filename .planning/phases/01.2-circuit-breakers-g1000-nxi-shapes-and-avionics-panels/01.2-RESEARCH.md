## Summary

The panel is complete except for three things this phase adds. (1) **51 circuit breakers** (verified from three photos; 38 in the three bus boxes, 10 in a lower row right of the ELT, 3 right of the flap block) as one new control kind `circuit-breaker` with states `in`/`out`, default `in`, id prefix `cb.`, drawn with a black cap, a static amp-rating numeral and, when out, a raised cap with a white ring. (2) **Glass frames and bezels**: both displays get the well-known shape (top frequency header, bottom 12-slot softkey legend row on the glass, 12 inert softkeys with an up-triangle on the bezel below, side bezel strips with knobs and six keys). (3) **Three inert avionics units** in the centre stack: audio panel (two key columns, volume knob, red DISPLAY BACKUP button), backup EFIS (attitude display, tape display, one knob) and autopilot column (NAV/HDG/ALT knobs, 6 x 2 keys).

The decisive finding is geometric: the real breaker grid is a **7-column x 6-row stair-step** of three outlined boxes plus 3 blank plugs, and with the project's own text metrics (B612 700 at size 6, 0.06em tracking, measured in Chromium: POSITION 31.1, TAXI/MAP 32.0, STALL HT. 32.0 units wide) it needs a column pitch of 36 units, i.e. about 260 units of width. The right edge of the existing panel leaves 200 units (MFD bezel ends at 1780, face plate at 1980) and the MFD right bezel strip still has to fit in there. The grid therefore **cannot fit in the 2000 x 1300 space**. Recommendation: widen the viewBox to about **2180 x 1300** by adding only to the right (nothing left of x 1980 moves, so every confirmed reference row keeps its position); this costs nothing on desktop (height-limited, scale stays 0.532) and about 7 to 9 percent scale on tablet and portrait phone. The second driver is the zoom guarantee: a hit footprint of 28 x 28 reaches 44 px on the phone profile only when a zoom region is at most three breaker rows tall, so the bus panel is split into three zoom regions (`cb_essential`, `cb_main`, `cb_low`) plus `cb_strip`.

**Primary recommendation:** Add `circuit-breaker` as a first-class registry kind (prefix `cb.`, flat ids such as `cb.gps_nav1`), generate the 51 `ControlSpec`s from one typed grid table (row, col, label lines, rating), split the bus panel into four regions on one new plate with a widened viewBox, keep all avionics artwork region-owned (so the existing art-fit and text-overlap gates enforce containment), and keep the glass/bezel work in separate files so plans can run in parallel.

### Pattern 1: Registry kind (answer to question 2)

`ControlDef` is a closed union and the kind prefix map is typed `Record<ControlKind, string>`, so adding a kind is a compile error until prefix, widget and `targetSide` exist. `[VERIFIED: src/engine/registry.ts:181-183, 229-236, src/ui/panel/ControlWidget.tsx:32-34]`

Quoted, verbatim:
```ts
// registry.ts:181-183
export type ControlDef =
  ToggleDef | GuardedToggleDef | GuardDef | DetentLeverDef | MomentaryButtonDef | RotaryDef;
// registry.ts:229-236
const KIND_PREFIX: Readonly<Record<ControlKind, string>> = {
  toggle: 'sw.',
  'guarded-toggle': 'sw.',
  guard: 'sw.',
  'detent-lever': 'lv.',
  'momentary-button': 'btn.',
  rotary: 'sw.',
};
```

Skeleton (new names only; every existing name used above is in the quote):
```ts
// registry.ts additions
export interface CircuitBreakerDef extends ControlBase {
  readonly kind: 'circuit-breaker';
  /** Exactly [in, out]. Labels are for aria only; nothing prints them (owner rule G-0.1). */
  readonly states: readonly [StateDef, StateDef];
  readonly default: 'in';
  /** Static amp rating printed on the cap, e.g. '5' or '7½'. */
  readonly rating: string;
  /** Static label lines printed above the cap (data, never computed); absent means [label]. */
  readonly labelLines?: readonly string[];
}
// ControlDef union gains CircuitBreakerDef; ControlSpec (Exclude<ControlDef, GuardDef>) follows.
// KIND_PREFIX gains 'circuit-breaker': 'cb.'.
// New invariant, called from defineRegistry like checkRotary:
function checkCircuitBreaker(def: CircuitBreakerDef): void {
  const [first, second] = def.states;
  if (first.id !== 'in' || second.id !== 'out' || def.default !== 'in') {
    throw new RegistryError(`breaker "${def.id}" must have states [in, out] and default "in"`);
  }
  if (def.rating.trim() === '') throw new RegistryError(`breaker "${def.id}" has no rating`);
}
```
`legalStates` needs no change (it falls through to `def.states.map`), `checkDistinctStates` and `checkDefaultLegal` already apply. `PanelStore` needs no change (kind-agnostic). `bridge.ts` needs no change.

Widget contract (copy `Toggle`, `[VERIFIED: src/ui/panel/widgets/Toggle.tsx:7,85-106]`): primary pointers only, `setPointerCapture`, remember pointerdown, on pointerup within `TAP_SLOP_PX` (10) call `bridge.actuate(def.id, otherState)`; never listen to `click`. `tapTarget(states, current, fraction)` is exported from `Toggle.tsx` and already flips a two-state control, reuse it. DOM contract (to be asserted by unit and e2e tests): outer `<g data-control-id={id} data-kind="circuit-breaker" data-state={state} role="img" aria-label={`${label}: ${stateLabel}`} transform=translate(x y)>`; a `<rect data-hit={id}>` of `def.hit`; inside the body a `data-breaker-ring` element that exists **only** in state `out` (the white ring) and a `data-breaker-cap` element whose `transform` or radius differs between states (raised cap). `data-hit` makes `zoom.ts` treat the pointer as a control pointer `[VERIFIED: src/ui/panel/zoom.ts:15 TAP_TARGET_SELECTOR]`.

Art (static only; sizes must be 6, 8, 10 or 14, the project type scale `[VERIFIED: UI-SPEC lines 108-125]`): in state `in` a flush black cap r 11 (`#15171a`, rim `#3a3f46`) with the rating numeral at size 8 centred, plus a dark bezel ring r 13; in state `out` the cap is drawn raised (offset 2 up, larger shadow ellipse offset 3 down, radius 11.8) and a white ring (`#f2f4f7`, stroke 2.5, r 12.5) is added around the base. The label lines (size 6, `#aab3bd`) sit above the cap and are identical in both states. State is therefore readable without colour (raise plus ring shape), and no `data-state-text` exists (`e2e/static-text.spec.ts` asserts zero such nodes). `[VERIFIED: e2e/static-text.spec.ts:39-42]`

`targetSide` (viewport.ts line 100, a switch with no default `[VERIFIED: src/ui/panel/viewport.ts:100-122]`) gets `case 'circuit-breaker': return Math.min(def.hit.w, def.hit.h);`.

### Pattern 2: Grid-table generation (answer to the Claude's-discretion item)

One typed table row per breaker: `{ id, lines, rating, region, col, row }`, plus constants `PITCH_X = 36`, `PITCH_Y = 44`, `HIT = { w: 28, h: 28 }` for the bus boxes and `PITCH_X = 26`, `HIT = { w: 24, h: 28 }` for the lower row. The generator computes `x`, `y` from the cell, so a re-pitch is a one-line change. The layout test must NOT import the generator's constants: `tests/layout-reference.ts` gets a separate literal `CB_REFERENCE` (id, row, col) written out independently, and the test checks `centre = origin + col * pitch` within tolerance and the relations (same row means same y, same column means same x, c7 pumps right of c6, and so on). This keeps the reference a genuine second source, as the existing rows are.

### Pattern 3: Region-owned avionics art

Region ids for inert art map to frame components exactly like `FRAMES = { pfd: PfdFrame, mfd: MfdFrame }` `[VERIFIED: src/ui/panel/Panel.tsx:14-17]`. Art inside `[data-region-id]` groups is measured by `e2e/art-fit.spec.ts` (must lie inside the region frame and the carrying plate, tolerance 0.75), and every text enters the text-overlap gate; the gate skips only the `pfd` and `mfd` regions `[VERIFIED: e2e/art-fit.spec.ts:142, 105]`. Therefore: draw bezel strips, audio, standby and autopilot art in their own regions, never inside `PfdFrame`/`MfdFrame` beyond the screen bounds (that would escape the gate).

### Anti-Patterns to Avoid
- **IN/OUT text, "PULLED" captions, or any `data-state-text`:** violates G-0.1 and the e2e gate.
- **One 260 x 330 region for the whole bus panel:** phone tap size 28 x 1.0 about 28 px, fails `tests/zoom.test.ts` and `e2e/zoom.spec.ts`.
- **Bus segment in the id** (`cb.ess.sam`): bus membership is uncertain and ids are permanent.
- **Drawing avionics art in the shell layer:** not covered by the art-fit gate, so "parts inside their plates" would be unenforced.
- **Unicode glyphs for arrows and triangles:** outside the font `unicode-range`; draw as paths.
- **Extra "GO-AROUND" strings:** the brand tests require exactly 2 `[VERIFIED: tests/panel-shell.test.ts:119, e2e/brand.spec.ts]`.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Breaker legal state, event log, graded history | custom state in the widget | `PanelStore.dispatch` through `bridge.actuate` | Interlock, `unchanged` rejection and the event log already exist and are what Phase 2 grades. |
| Tap vs drag discrimination | new gesture code | `Toggle`'s pointer contract and exported `tapTarget` | Proven on every device project; zoom arbitration depends on `data-hit`. |
| Zoom-to-region for the grid | custom pan/zoom | new regions + existing `zoom.ts` | Region model is the project's zoom mechanism (PNL-09). |
| Tap-size guarantee | per-widget size hacks | `targetSide` + `tests/zoom.test.ts` | One formula already gates every region and profile. |
| Label wrapping | runtime text measurement | data-stored `labelLines` | Deterministic; the text-overlap gate measures the real DOM anyway. |
| Per-breaker layout reference rows by hand | 51 hand-typed `{x,y}` rows | grid table plus an independent `(row, col)` reference list | One pitch change would otherwise touch 51 rows. |
| Arrows, triangles, slashed circle | font glyphs | SVG paths | Not covered by the self-hosted font's `unicode-range`. |

**Key insight:** every gate this phase must satisfy already exists and is data-driven. The work is to feed the existing registry, region, plate and test machinery new data, not to invent new mechanisms.

## Common Pitfalls

### Pitfall 1: Hard-coded counts
**What goes wrong:** tests assert today's totals and fail the moment breakers land.
**Where (all `[VERIFIED]` this session):** `tests/layout.test.ts:423-427` (`'has exactly 41 non-guard controls, 13 lamps and 19 regions'`), `tests/registry.test.ts:545-546` (`'has 41 non-guard controls after the de-ice rebuild of plan 22'`), `tests/panel-review.test.ts:48` and `README.md:13` (`'41 controls and 13 indicator lamps in 19 regions'`), `e2e/layout.spec.ts:5-23` (`REGION_IDS` list and `toHaveCount(REGION_IDS.length)`), `tests/panel-shell.test.ts:148-153` (`'draws two display bezels and three reserved centre-stack outlines'`) and `:169-174` (`'draws bus brackets with headings only, no circuit-breaker shapes (PNL-12 is 01.2)'`, `bus-bracket` count 3).
**How to avoid:** derive the new expected numbers from the grid table (92 non-guard controls = 41 + 51; regions 19 + 4 breaker regions + any avionics regions; lamps stay 13) and update README in the same plan. Rewrite the two shell tests (reserved outlines and "no breaker shapes") instead of deleting coverage.

### Pitfall 2: Reference table completeness gate
`'every non-guard control appears in the reference table'` and `'the reference tables cover every non-guard control and every lamp exactly once'` compare `REFERENCE_POSITIONS` to all registry controls `[VERIFIED: tests/layout.test.ts:229-251]`. Adding 51 controls without extending the gate fails it. Extend the expectation to `REFERENCE_POSITIONS` plus the new `CB_REFERENCE` ids (union, no duplicates), keep `tol` semantics (3 confirmed, 8 unconfirmed) and mark the flap-strip breakers 8.

### Pitfall 3: Panel label table parser ignores `cb.`
`ID_PATTERN = /^(sw|btn|lv|lt)\.[a-z_0-9]+$/` `[VERIFIED: tests/panel-labels.test.ts:39]` means `cb.*` rows in `docs/PANEL-LABELS.md` are invisible and the test `'names every registry control id and every lamp id'` fails for all 51. Change the pattern to include `cb`, and add a "Circuit breakers" section. A row may list several ids in the first cell (`firstCell.matchAll`), so one row per grid row is enough. The same file forbids the word "planned" and real brand names in the doc.

### Pitfall 4: Art-fit and text-overlap gates (e2e, desktop-chromium, 2000 x 1400 viewport)
Region art must lie inside the region frame and the carrying plate (0.75 tolerance); every `<text>` pair must not overlap by more than 0.5 square units, `TEXT_OVERLAP_KNOWN` is empty and a stale entry fails `[VERIFIED: e2e/art-fit.spec.ts:18, 185-212]`. Consequences: label lines (two lines at size 6, 7 apart) need a 16-unit label band inside the region above the first row; bus headings (shell text, owner `shell`) must not touch the label band; a label wider than its column gap fails the gate. **The gate viewport is 2000 x 1400 "where one unit is about one pixel"** `[VERIFIED: e2e/art-fit.spec.ts:51]`; with the widened viewBox set it to at least 2200 x 1400 (otherwise the panel scales below 1 px per unit and tolerances change).

### Pitfall 5: Hard-coded viewBox strings
`e2e/zoom.spec.ts:7` (`'0 0 2000 1300'`), `e2e/smoke.spec.ts:30`, `tests/layout.test.ts:109` (`expect(VIEWBOX).toEqual({ w: 2000, h: 1300 })`), `tests/zoom.test.ts:106` (a corner at x 2000), `e2e/zoom.spec.ts:341` (`mid.w < 2000`), plus the shell paths listed above `[VERIFIED: grep this session]`. Replace the literals by an import of `VIEWBOX` where possible.

### Pitfall 6: Plates and regions
"No two plates overlap", "no plate overlaps the PFD or MFD bezel (region grown by 16)", "every region a plate names is carried by one plate only", "every footprint of a carried region lies inside its plate" `[VERIFIED: tests/layout.test.ts:453-536]`. The MFD right bezel strip and the bus plate must not overlap (1866 vs 1874). Regions must not overlap (`:130-140`); `cb_strip` ends 1560 against the fuel-placard decor (static, not a region), ELT region starts 1720.

### Pitfall 7: Background clearance
Each region needs a background point at least 7 units from every footprint inside its inner 80 percent `[VERIFIED: tests/layout.test.ts:305-327]`. A dense grid passes only through the row gaps (row pitch 44 minus hit 28 gives 8). Do not enlarge hits to fill the cell (e.g. 36 x 44) or the test fails.

### Pitfall 8: Kind-exhaustive spots
Compile errors by design: `KIND_PREFIX`, `ControlWidget` switch (`unsupported(def: never)`), `targetSide` switch. Runtime-only spots (no compile error): `tests/zoom.test.ts` and `tests/registry.test.ts` fixtures, `static-text.test.ts` families (add a "circuit breaker family text is state-independent" block), `README.md` counts.

### Pitfall 9: State text rule
The owner rule beats D-02. `e2e/static-text.spec.ts` asserts the panel's text list is identical before and after operating controls and that no `[data-state-text]` exists; the breaker label and rating are state-independent so they pass, an IN/OUT text would fail.

### Pitfall 10: Font size scale
Source-scanning tests read `font-size={N}` in specific skin files and accept only the declared scale `[VERIFIED: tests/button-skins.test.ts:102-111, rotary.test.ts:422, indicators.test.ts:528]`. New skin files must use only 6, 8, 10, 14 (numeral 8, labels 6, headings 8). Use numeric JSX literals in the same `font-size={6}` style so the scanners see them.

### Pitfall 11: Accidental breaker toggles on small screens
See "Zoom behaviour on the full view" (Q5). Also: `PNL-06` says stray touches on neutral areas must never be graded; the labels and plate art are `pointer-events: none`, only the 28 x 28 hit rects are controls.

### Pitfall 12: Full panel button covering a hit
Zoom e2e fails if the button overlaps any hit of the zoomed region `[VERIFIED: e2e/zoom.spec.ts:260-278]`. Keep at least 30 units of non-hit band above the first row of right-hand regions.
